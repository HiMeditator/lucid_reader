# Lucid Reader 功能规划

本文档记录 Lucid Reader 的产品功能范围和关键体验设计。开发进度和验收状态见 [PROGRESS.md](./PROGRESS.md)，技术架构见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 1. 功能范围

### 1.1 P0：MVP 必须完成

- 书库管理
  - 导入本地文件。
  - 展示书名、作者、格式、封面、最近阅读时间、阅读进度。
  - 删除书籍记录，并可选择是否删除本地缓存。
- 文档阅读
  - TXT 阅读。
  - EPUB 阅读，包括目录、章节跳转、基础样式。
  - PDF 阅读，包括分页、缩放、页码跳转。
  - MOBI 作为实验格式，优先支持无 DRM 的基础文本提取。
- 阅读状态
  - 记录阅读位置、字体大小、主题、行距、边距、分页或滚动模式。
  - 支持亮色、暗色、护眼主题。
- 界面多语言
  - 初始支持英语、中文、日语三种界面语言。
  - 支持跟随系统语言，也支持用户在设置页手动选择界面语言。
  - 用户可见文案、错误提示、空状态、菜单、设置项和通知文案都通过本地化资源管理。
  - 后续添加新语言时，应主要通过新增语言资源和注册 locale 元数据完成，不要求改动业务逻辑。
- 大模型接入
  - 支持 OpenAI 兼容 Chat Completions 或 Responses 风格接口。
  - 支持 Ollama 本地接口。
  - 支持 Anthropic 兼容接口。
  - 支持模型配置、连通性测试、超时、重试、流式输出。
- 选中文本 AI 操作
  - 翻译。
  - 总结。
  - 解释。
  - 自定义提示词。
- 双语阅读基础版
  - 以段落为单位生成目标语言译文。
  - 原文与译文上下对照或左右对照。
  - 翻译结果缓存，避免重复调用。
- 语义检索基础版
  - 对单本书进行分块、Embedding、向量检索。
  - 支持自然语言查询。
  - 返回相关片段、章节、位置。
- 基于书籍问答
  - 基于当前书籍进行 RAG 问答。
  - 回答中附带引用片段。
  - 支持继续追问。

### 1.2 P1：首个稳定版

- 书库增强
  - 批量导入。
  - 自动提取封面、作者、语言、简介。
  - 按作者、标签、格式、阅读状态过滤。
- 阅读增强
  - 书签、划线、笔记。
  - 全文关键词搜索。
  - EPUB 样式优化与脚注处理。
  - PDF 文本层提取与选区支持。
- 双语阅读增强
  - 按章节预翻译。
  - 翻译质量模式：直译、意译、术语一致。
  - 用户术语表。
  - 翻译失败片段重试。
- TTS
  - 系统 TTS。
  - 云端 TTS Provider。
  - 本地 TTS Provider。
  - 朗读队列、语速、音量、断点续读。
- RAG 增强
  - 跨书库检索。
  - 混合检索：关键词检索 + 向量检索。
  - 重排 rerank 接口预留。
  - 索引状态可视化。
- 同步预留
  - 设计数据结构时预留多设备同步字段。
  - 暂不实现云同步，避免过早扩大边界。

### 1.3 P2：后续扩展

- 多设备同步。
- 插件系统。
- OCR 与扫描版 PDF 支持。
- 漫画、图片型书籍支持。
- 学术阅读模式：引用管理、BibTeX、论文摘要。
- 阅读统计与学习计划。
- 共享提示词模板市场。
- 私有知识库与多书集合问答。

## 2. 文档解析与阅读策略

### 2.1 TXT

- 检测编码，统一转为 UTF-8 处理。
- 基于空行、章节标题规则进行段落和章节切分。
- 对超大 TXT 使用流式读取和分页缓存。

### 2.2 EPUB

- 解析 OPF、NCX/Nav、章节 HTML、CSS、图片资源。
- MVP 阶段先将章节转换为内部富文本模型，再渲染为 Flutter Widget。
- 保留原始章节 href 与位置映射，供目录跳转、引用和翻译缓存使用。

### 2.3 PDF

- MVP 优先稳定显示页面、缩放、跳页。
- 文本提取能力用于搜索、选区、RAG；若无法提取文本，应明确提示用户该 PDF 可能是扫描版。
- PDF 阅读位置以页码、缩放和滚动偏移保存。

### 2.4 MOBI

- 只支持无 DRM MOBI。
- 作为实验功能处理，优先实现元数据提取和正文文本提取。
- 若 Flutter/Dart 生态支持不足，可考虑通过平台适配或转换流程处理，但要隔离在基础设施层。

## 3. AI 接入设计

### 3.1 Provider 抽象

统一定义以下接口：

- `ChatModelClient`
  - 普通回复。
  - 流式回复。
  - 工具或函数调用能力预留。
- `EmbeddingClient`
  - 单条文本向量化。
  - 批量向量化。
  - 维度检查。
- `TranslationService`
  - 单段翻译。
  - 批量翻译。
  - 术语表和风格参数。
- `TtsClient`
  - 文本转音频。
  - 流式音频预留。
  - 语音列表查询。

Provider 类型：

- OpenAI 兼容接口
  - 适配自建网关、OpenAI 兼容服务、本地代理。
- Ollama
  - 重点支持本地 chat 和 embedding。
  - 需要检测服务是否运行，并提供错误提示。
- Anthropic 兼容接口
  - 适配 Claude 风格消息结构。
  - 内部统一转换为通用消息模型。

### 3.2 模型配置

配置项：

- Provider 名称。
- 接口类型。
- Base URL。
- API Key。
- 默认聊天模型。
- 默认翻译模型。
- 默认 Embedding 模型。
- 默认 TTS 模型。
- 超时时间。
- 最大并发数。
- 请求速率限制。

API Key 不应明文散落在业务数据中。Android 优先使用安全存储；Windows 优先使用系统凭据或加密存储。调试日志必须隐藏密钥。

### 3.3 提示词模板

内置模板：

- 翻译当前段落。
- 总结当前章节。
- 解释选中文字。
- 提取术语。
- 基于书籍回答问题。

模板变量：

- `source_language`
- `target_language`
- `book_title`
- `section_title`
- `selected_text`
- `surrounding_context`
- `retrieved_chunks`
- `user_question`

用户可编辑模板，但要提供恢复默认值。

## 4. 双语阅读设计

双语阅读应按“片段级缓存”实现，而不是直接生成整本译文文件。

流程：

```text
Reader visible range
  -> collect paragraphs
  -> check translation cache
  -> request missing translations
  -> render original + translation
  -> persist cache
```

关键点：

- 以 `content_hash + target_language + provider + model + prompt_hash` 判断缓存命中。
- 可设置只翻译当前可见内容、当前章节、整本书。
- 翻译请求应批量合并，但结果必须能映射回原段落。
- 失败段落显示重试入口，不阻塞其他段落。
- 需要语言检测；若源语言与目标语言相同，可跳过翻译。
- 支持术语表，保证人名、概念、专有名词一致。

## 5. TTS 设计

TTS 分三层：

- 系统 TTS：优先用于 MVP，接入成本低，离线能力取决于系统。
- 云端 TTS：质量高，但有网络、费用和隐私风险。
- 本地 TTS：适合隐私和离线使用，但模型体积、性能、部署复杂度更高。

朗读能力：

- 朗读当前段落。
- 从当前位置连续朗读。
- 朗读选中文字。
- 按章节生成朗读队列。
- 支持播放、暂停、停止、上一段、下一段。
- 支持语速、音调、音量。
- 支持按语言选择语音。

缓存策略：

- 短文本可实时生成。
- 章节朗读可后台生成音频缓存。
- 缓存 key 应包含文本 hash、语言、voice、speed、provider、model。
- 用户应能清理 TTS 缓存。

## 6. 语义检索与 RAG 设计

### 6.1 分块

分块目标是兼顾语义完整性和检索精度。

建议策略：

- EPUB/TXT：优先按章节、段落切分，再合并到目标 token 范围。
- PDF：优先按页和段落切分，保留页码。
- chunk 过长时二次切分，过短时与相邻段落合并。
- 每个 chunk 保存章节、位置、页码、段落序号等来源信息。

### 6.2 索引

索引流程：

```text
parse document
  -> normalize text
  -> split chunks
  -> compute content hash
  -> skip unchanged chunks
  -> create embeddings
  -> write vector index
  -> mark index status
```

索引状态：

- 未索引。
- 等待中。
- 索引中。
- 已完成。
- 部分失败。
- 需要重建。

### 6.3 检索

MVP：

- 向量相似度检索。
- 返回 top-k chunks。
- 在回答中附带引用。

稳定版：

- 关键词检索 + 向量检索混合。
- 可选 rerank。
- 支持当前章节、当前书籍、整个书库三种范围。
- 支持按语言过滤。

### 6.4 问答

回答生成流程：

```text
user question
  -> detect scope
  -> retrieve chunks
  -> build grounded prompt
  -> stream answer
  -> show citations
  -> save conversation
```

约束：

- 如果检索内容不足，应提示“当前书籍中没有找到足够依据”，不能假装有来源。
- 引用应能跳转到原文位置。
- 用户可展开查看模型使用的上下文片段。

## 7. 界面多语言设计

界面语言只控制应用 UI，不自动改变书籍语言、翻译目标语言或 TTS 朗读语言。翻译和 TTS 的语言偏好需要在各自功能中单独配置。

初始 locale：

- `en`：英语。
- `zh`：中文。MVP 可先使用简体中文资源，后续保留拆分 `zh-Hans`、`zh-Hant` 的能力。
- `ja`：日语。

语言切换：

- 默认跟随系统语言。
- 设置页提供英语、中文、日语和“跟随系统”选项。
- 不支持的系统语言回退到英语或用户上次选择的语言。
- 切换语言后，导航、设置、阅读工具栏、错误提示、空状态、任务状态和对话入口应立即更新。

扩展要求：

- 本地化资源以稳定 key 管理，避免使用源语言文案作为 key。
- 日期、数字、阅读进度、文件大小等格式化应基于当前界面 locale。
- 添加新语言的标准流程应包括新增资源文件、注册 locale、补齐基础页面截图或测试。

## 8. UI 信息架构

主要页面：

- 书库页
  - 最近阅读。
  - 全部书籍。
  - 导入入口。
  - 索引状态提示。
- 阅读页
  - 顶部阅读工具栏。
  - 目录侧栏。
  - 正文区域。
  - 选中文字浮动菜单。
  - AI 侧栏。
  - TTS 迷你播放器。
- 搜索页
  - 关键词搜索。
  - 语义搜索。
  - 检索范围选择。
- AI 对话页
  - 当前书籍问答。
  - 引用片段。
  - 历史会话。
- 设置页
  - 模型 Provider。
  - 界面语言。
  - 翻译目标语言。
  - TTS。
  - 阅读外观。
  - 隐私与缓存。

Windows 宽屏布局建议：

```text
左侧导航 | 中间阅读区 | 右侧 AI / 目录 / 笔记面板
```

Android 布局建议：

```text
阅读区为主；目录、AI、设置通过底部抽屉或独立页面进入
```
